# G-IMPACT 에너지 에디션

기후테크 기업용 비즈니스 코칭 소개 페이지입니다. 피그마 파일의 **에너지에디션_수정2** 프레임을 정적 HTML로 옮겼고, Firebase Hosting 기본 사이트에 배포되어 있습니다.

이 문서는 다른 컴퓨터에서 저장소를 열었을 때, 어떤 시안이 맞고 어디가 아직 시안과 다른지 알 수 있게 적었습니다.

## 배포 주소

| 항목 | 값 |
| --- | --- |
| 라이브 사이트 | https://g-impact-dfe3b.web.app |
| Firebase 앱 도메인 | https://g-impact-dfe3b.firebaseapp.com |
| Firebase 프로젝트 | `g-impact-dfe3b` |
| Hosting 사이트 | `g-impact-dfe3b` (프로젝트 기본 사이트) |
| 콘솔 | https://console.firebase.google.com/project/g-impact-dfe3b/hosting/sites |

같은 프로젝트의 추가 사이트 `g-impact`(`https://g-impact.web.app`)는 호스팅이 중지된 상태입니다. 배포 대상은 기본 사이트뿐입니다. 사이트 자체는 지우지 않았습니다.

라이브 사이트는 수정2 페이지입니다. GitHub `main`의 마지막 커밋 `2a35cf5`는 그 이전의 잘못된 시안입니다. 수정2의 `public/index.html`, `public/styles.css`, `public/assets` 추가 파일은 아직 커밋되지 않았습니다. 다른 컴퓨터에서 `git pull`만 하면 라이브 사이트와 다른 옛 페이지가 나옵니다.

## 어디까지 시안 수치로 맞췄는지

수정2 프레임이 너무 길어서 전체를 한 번에 받으면 글자 크기와 간격이 빠집니다. 한도에 걸리기 전에 구역마다 따로 받은 곳은 글자 크기, 색, 간격, 모서리를 그 수치로 넣었습니다.

수치를 받은 구간:

- 헤더, 히어로, 고민 말풍선, 해답 카드 01–03
- 인터뷰 화면, 성과 사례의 제목·태그·수상 결과
- 사업화와 경영 카드 세 장, 이후 이어지는 다섯 칸
- 비교표, 후기 제목과 일부 인용, 기관 카드

한도 때문에 수치와 원문을 못 받은 구간은 앞 구간의 스타일을 이어서 최대한 비슷하게 넣었습니다. 시안과 다른 곳은 아래 여섯 곳입니다.

1. 자주 묻는 질문의 답변 뒷문장. 질문 7개는 맞고, 답변은 중간에서 잘렸습니다.
2. 성과 사례 카드 안의 본문. 제목, 태그, 수상 결과는 시안과 같습니다.
3. 후기 네 장 중 긴 인용 세 개. “제 주변에 이쪽으로 정말 탁월한 분은 코치님 한 분뿐이에요.”는 원문입니다.
4. 임팩트 증명 카드 04–06. 이름은 확인했고, 카드 안 설명은 결과물 이름입니다.
5. 보고서 샘플 이미지. 이름만 있는 칸입니다.
6. 푸터 주소. “에너지산업융” 뒤에서 잘렸습니다.

넓은 화면은 수정2의 가로 구성을 유지합니다. 좁은 화면에서는 카드와 표가 아래로 쌓입니다. 글꼴은 [Pretendard](https://github.com/orioncactus/pretendard) CDN입니다. 이미지는 `public/assets`에 받아 두었고, 피그마의 임시 주소는 페이지에 넣지 않았습니다.

## 피그마 한도

Starter 계정의 Figma MCP 읽기 호출은 한 달에 최대 20번입니다. 2026-11-04에 그 한도를 다 썼습니다. 공식 문서는 매월이라고만 하고, 1일인지 결제일인지 처음 쓴 날부터 30일인지 공개하지 않습니다. `whoami`에도 남은 횟수나 초기화 시각은 없습니다.

캡처만으로는 글자 크기, 자간, 간격, 색을 확정할 수 없습니다. MCP가 주는 것은 그 수치와 원문, 이미지 파일입니다. 한도가 풀리기 전에 여섯 구간을 맞추려면 다음 중 하나가 필요합니다.

- 해당 구간 캡처와 함께, 피그마 오른쪽 패널의 크기·글자·색·간격을 전달
- 개인 액세스 토큰으로 REST API 호출. 토큰 발급 자체는 무료이고 MCP 월 20회와는 다른 횟수입니다. 다만 이 파일이 Starter 팀에 있어 파일 내용을 읽는 호출도 달마다 몇 번으로 제한됩니다. 문서 표는 최대 20번, 본문 예시는 6번이라 정확한 숫자는 서로 다릅니다. 토큰은 저장소와 채팅에 넣지 않습니다.
- Professional 이상에서 Full 또는 Dev 시트를 쓰면 MCP 읽기가 하루 200번이 됩니다.

## 페이지 구성

1. 헤더: Problem, Solution, Process, Review, 문의하기
2. 히어로: 기후테크 에디션, 870건, 54곳, 무료 상담
3. 고민 말풍선과 해답 카드 01–03
4. 대면 인터뷰 화면
5. 성과 사례와 기후금융 문구
6. 과정 카드: 사업화와 경영, 임팩트 증명, 이후 다섯 칸, 결과물 이름
7. 타 서비스 비교
8. 후기, 기관 안내, 자주 묻는 질문
9. 상담 폼과 푸터

메뉴와 상담 버튼은 같은 페이지의 해당 위치로 이동합니다. 상담 폼은 저장소가 없는 정적 폼입니다.

## 디렉터리

```
public/
  index.html          페이지 마크업
  styles.css          스타일
  assets/             피그마에서 받은 이미지와 SVG
firebase.json         Hosting 공개 디렉터리와 사이트 설정
.firebaserc           기본 Firebase 프로젝트
```

Firebase CLI가 만드는 `.firebase/` 캐시와 로컬 Cursor 설정은 저장소에 포함하지 않습니다.

## 로컬에서 보기

`public`이 정적 파일의 루트입니다.

```powershell
cd public
python -m http.server 5500
```

브라우저에서 http://localhost:5500 을 엽니다.

## 다시 배포

Firebase CLI에 `g-impact-dfe3b` 프로젝트 권한이 있는 계정으로 로그인되어 있어야 합니다. Windows에서는 `firebase.ps1`이 멈추므로 `firebase.cmd`를 씁니다.

```powershell
firebase.cmd deploy --only hosting --project g-impact-dfe3b
```

`firebase.json`의 Hosting 사이트 이름이 `g-impact-dfe3b`이므로, 이 명령은 기본 사이트만 갱신합니다. 배포가 끝나면 https://g-impact-dfe3b.web.app 에 반영됩니다.
